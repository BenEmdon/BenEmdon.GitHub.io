Removing the merge queue

October 2026

This series is about one thing: how we get to the next magnitude of agent scale.

Thesis

The merge queue is a human-scale synchronization primitive. At agent scale it becomes the bottleneck. Removing it is what gets us to the next magnitude of agent scale.

Where we are

We serialize landings through a global queue so main is always green at merge time. It worked when humans merged hundreds of changes a day. As agents push that volume into the thousands, queue wait time starts to dominate the change lifecycle, and the global lock gets harder and more expensive to hold. We built automation to cut time-to-production; the queue is now the thing standing in its way.

The bet

Stop trying to keep main green at merge time. Anthropic hit the same wall at 30,000 merges a day:1 they could not replicate a global repository lock at that rate, so they moved the quality bar to post-merge and pre-deploy automated testing. Concurrent changes can conflict, and agents fix those conflicts faster than humans can even identify them. I buy this completely.

The new contract: land fast, verify continuously, revert forward.

  • Speculative merging replaces the serialized queue. Changes land without waiting on each other.
  • Post-merge signal pipelines run the full test suite against main continuously. Main is healthy on average and quickly repaired, not green at every instant.
  • Agent-driven conflict repair and automatic revert-forward handle breakages in minutes, not the hours a human-driven revert chain takes.
  • The deploy gate becomes the real quality bar. Pre-deploy verification is where safety lives now, with trunk health SLOs backing it.

This is not lowering standards. It is admitting that a global lock was always a proxy for “we will catch it before users see it,” and the proxy does not scale. The deploy gate is the thing we actually meant.

What we build

  1. Speculative merging: land changes without serializing on a queue.
  2. Post-merge signal that runs the full suite against main continuously, with fast, automatic revert-forward.
  3. Agent-driven conflict repair as a first-class pipeline, not a human pager event.
  4. Pre-deploy gates hardened into the real quality bar, with trunk health SLOs we actually hold.

Open questions

  • Which signals must stay pre-deploy for safety-critical code. That list needs to be explicit, not vibes.
  • Trunk health targets: how red can main get, and for how long, before we intervene structurally.
  • The rare conflict agents cannot resolve cleanly, and the escalation path for it.

1. Anthropic, “Redesigning source control” (Oct 2026): anthropic.com/engineering/redesigning-source-control. On the merge queue: “a proper merge queue doesn’t make much sense at agent scale.” ↩
