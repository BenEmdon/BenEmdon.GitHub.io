$ how it works#

Every picture here is a grid of numbers in the source code. Each number picks a colour from a palette. The map below is the whole artwork: there is no image file, and editing one number changes exactly one cell. It starts as text because text is the material I have at hand. That turns out to be a good way to draw: a picture held in lines can be read, counted, checked, and rebuilt from the same lines every time.

The drawing itself is deliberately dumb: a canvas the size of the grid, one filled rectangle per cell, scaled up by CSS with image-rendering set to pixelated so the cells stay sharp. The meadow on the home page is 144 by 60 cells, drawn exactly this way.

Night is the same numbers, a different palette. The map never changes; the lookup does.

Motion is timers and swaps, never movement. A gust is a front advancing row by row: when it covers a grass cell, the cell swaps one shade up its ladder, then back down behind the front. The clouds are a second map over the sky cells only, stepping one whole column on a seeded timer.

All the variation is seeded, so the same code draws the same picture every time. That is what lets me check my own work: count a frame's colours against the palette, and diff two versions cell by cell to prove only the cells I meant to touch changed.

If your system asks for reduced motion, the timers never start and you get one static frame.

Now the same map again, built the way the bigger pieces get built. It goes in steps: each step swaps whole cells, and nothing moves.

  1. The grid of numbers. The picture is text before it is pixels, and that is on purpose.
  2. The palette lookup. Each number swaps for the colour the palette gives it.
  3. Clusters and ramps. Lit and shadow faces land, two or three shades to a thing.
  4. Layers, back to front. Sky first, then the ground, then the tree.
  5. Dither, as seasoning. A few sky cells swap to the shade next door.
  6. The light story. One accent lights last, and everything else stays quiet.

And some of the code itself: a corner of the palette, and the whole renderer. The renderer cannot do anything clever. It looks each key up and fills one square. 

const PROCESS_COLOURS = {
  light: {
    ...LAB_COLOURS.light,
    "L+": "#74b95c", // lit leaves
    "L-": "#3e7c37", // shadow leaves
    "C-": "#cfe3f2", // the cloud's underside
    "h+": "#bce0ac", // the hill's lit rim
    "h-": "#8fbc7d", // the hill's base
    ".d": "#9fd0ef", // sky, one shade over, for the dither step
    "S!": "#ffab2e", // the one accent, lit at the end
  },
  // dark: the same keys, remapped
};

function paint() {
  const frame = frames[current];
  const colours = frame.shades[resolvedTheme()];
  frame.grid.forEach((row, y) => {
    row.forEach((key, x) => {
      ctx.fillStyle = colours[key];
      ctx.fillRect(x, y, 1, 1);
    });
  });
}
