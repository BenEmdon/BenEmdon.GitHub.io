$ how it works#

Every picture here is a grid of numbers in the source code. Each number picks a colour from a palette, and the map below is the whole artwork: there is no image file. Edit a number, and exactly one cell changes.

The drawing itself is deliberately dumb. A canvas the size of the grid, one filled rectangle per cell, and CSS scales it up with image-rendering set to pixelated, so the cells stay sharp. The meadow on the home page is 144 cells wide and 60 tall, drawn exactly this way.

Night is the same numbers with a different palette. The map never changes; the lookup does, and one repaint swaps every cell to its night colour.

Motion is timers and swaps, never movement. A gust is a front that advances row by row: each grass cell carries a shade step, and when the front covers it, the cell swaps one shade up its ladder, then back down behind the front. The clouds are a second map laid over the sky cells only, stepping one whole column on a seeded timer.

All the variation is seeded, so the same code draws the same picture every time. That is what lets me check my own work: count the colours in a frame against the palette, and diff two versions cell by cell to prove only the cells I meant to touch have changed.

If your system asks for reduced motion, the timers never start and you get one static frame.

Now a turn for you. Pick a colour, tap the cells, stamp a tree. A cell is on, or it is not.

That is the whole machine. Steal it.

The full instructions I work from are in this repo, unedited: the skill, the anchor template, the critique checklist, and the site palette.
